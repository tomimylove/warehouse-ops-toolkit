# Design System

Один визуальный язык для всех модулей — определяется один раз здесь, дальше
только переиспользуется. Ничего специфичного под конкретный модуль сюда не
попадает.

Ревизия: перенесено из валидированного дизайна FSA-версии (Jira/Atlassian-
близкий регистр — структурный, плотный, не "мягкий/декоративный"), а не
придумано заново. Первая версия этого документа (Archivo/IBM Plex Sans,
свой синий) заменена после прямого сравнения — старый дизайн был явно
сильнее продуман (иконки, тултипы, hover/active-состояния, тактильные
микро-анимации на кнопках).

## Шрифты

- **Inter** — единственный шрифт интерфейса (заголовки и тело). Структурный,
  плотный, не декоративный — читается как рабочий инструмент, не лендинг.
- **IBM Plex Mono** — только данные: id, даты, координаты, метры/сантиметры
  на Фотоплане, номера ячеек на Изометрической схеме.

Обе гарнитуры — с Google Fonts, подключаются один раз в `global.css`.

## Цвет

Токены — CSS custom properties в `src/styles/tokens.css`. **Тёмная тема —
явный переключатель в приложении (кнопка в сайдбаре), не `prefers-color-
scheme`** — осознанное решение, перенесённое из FSA-версии: на общем/
киоск-компьютере системная тёмная тема не должна тихо переключать и это
приложение тоже.

| Токен | Светлая тема | Тёмная тема | Назначение |
|---|---|---|---|
| `--color-bg` | `#F4F5F7` | `#0E1014` | Фон страницы |
| `--color-surface` | `#FFFFFF` | `#1A1D24` | Карточки/панели |
| `--color-surface-2` | `#EEF0F3` | `#23262F` | Вложенные/чуть темнее панели |
| `--color-border` | `#DFE1E6` | `#2B2F3A` | Тонкие границы |
| `--color-border-strong` | `#C1C7D0` | `#3D4250` | Границы кнопок/акцентных полей |
| `--color-text` | `#172B4D` | `#E7E9EE` | Основной текст |
| `--color-text-muted` | `#6B778C` | `#9099A8` | Второстепенный текст |
| `--color-accent` | `#2563EB` | `#5B93FF` | Интерактивные элементы, ссылки |
| `--color-success` | `#16A34A` | `#3DDC84` | Состояние: хорошо/выполнено |
| `--color-warning` | `#B25000` | `#F0A94E` | Состояние: требует внимания |
| `--color-danger` | `#DE350B` | `#FF6B5E` | Состояние: ошибка/критично |

Активный пункт навигации — не сплошная заливка, а полоса слева 3px +
подсветка фона через `color-mix(in srgb, var(--color-accent) 8%, var(--color-surface))`.
Тултипы (свёрнутый сайдбар) — фиксированный тёмный чип (`#23262F`/`#fff`)
независимо от темы, не токены — иначе в тёмной теме получается белое на
белом.

## Отступы и радиусы

Шкала отступов — кратна 4px: `--space-1` (4px) … `--space-7` (48px). Не
использовать произвольные значения вне шкалы. Радиус — `--radius-sm` (4px)
для мелких элементов (инпуты, бейджи), `--radius-md` (8px) для карточек.

## Базовые компоненты (`src/components/ui/`)

| Компонент | Назначение |
|---|---|
| `Button` | primary / secondary / danger варианты |
| `Input`, `Textarea` | поля форм |
| `Card` | панель-контейнер (список, форма) |
| `Badge` | статус-пилюля (success/warning/danger/neutral) — понадобится для occupancy на стеллажах |
| `PageHeader` | заголовок раздела + подзаголовок |
| `EmptyState` | "пока пусто" — для списков без данных |
| `Combobox` | поле с поиском по списку (например, выбор зоны склада) |
| `Table` | таблица с сортировкой по клику на заголовок |
| `Dialog` | модальное окно (подтверждения, формы) |
| `RichTextEditor` | форматированный текст (Tiptap, MIT-лицензия) — жирный/курсив/список, набор можно расширить, в `StarterKit` уже есть заголовки/цитаты/код |

**Fluent UI рассматривался и отклонён** (см. `ARCHITECTURE.md`) — своя система
даёт нужный внешний вид без веса и визуального языка Microsoft-продуктов.
Если позже понадобится докрутить доступность (клавиатурная навигация,
ARIA) без смены внешнего вида — смотреть в сторону headless-библиотек
(например, Radix UI Primitives), не в сторону Fluent.

Каждый компонент — самодостаточный `.tsx` + свой `.css` (обычные CSS-файлы,
без CSS-in-JS зависимостей). Модули приложения используют только эти
компоненты для типовых элементов интерфейса — не пишут кнопки/инпуты с нуля
у себя.

## Что не входит в эту версию

- Иконки продукта (не путать с иконками Изометрической схемы — те решаются
  отдельно, см. `ARCHITECTURE.md`, раздел про Digital Twin).
- Анимации/переходы — минимальные, только там, где помогают понять
  состояние (не ради красоты).
