# PRD — Warehouse Ops Toolkit

## Проблема

Разрозненные, неформальные способы вести повседневную операционную работу
склада (объявления, передача смены, справочная информация, схема объекта)
— бумага, чаты, отдельные файлы — без единого места, без ролей доступа, без
истории изменений.

## Цель

Единый, лёгкий инструмент под конкретные операционные процессы склада —
не полноценная WMS, не ERP. Модульная система: каждый модуль закрывает один
узкий, понятный процесс.

## Роли

- **admin** — полный доступ, управление пользователями и справочниками.
- **editor** — создание/редактирование контента в рамках своих модулей.
- **reader** — только просмотр.

Модель ролей уточняется на этапе core-слоя (см. `ARCHITECTURE.md`, п.8) —
не копируется автоматически из более ранних версий, пересматривается заново.

## Модули (первая волна)

| Модуль | Назначение |
|---|---|
| Announcements | Объявления для всей команды/подразделения |
| Handover | Передача смены — что сделано, что осталось, на что обратить внимание |
| Admin | Пользователи, роли, справочники |
| Digital Twin | Визуальная схема объекта — фотоплан (аннотированное фото) и изометрическая схема (параметрический план с адресуемыми объектами/ячейками) |

Точные требования и критерии приёмки — в `specs/features/NN-<module>.md`,
пишутся отдельно перед началом каждого модуля (см. процесс в
`ARCHITECTURE.md`, п.8).

## Вне скоупа (сейчас)

- Полноценный WMS-функционал (движение товара, инвентаризация в реальном
  времени) — не тема этого прототипа.
- Интеграции со сторонними системами учёта — рассматриваются отдельно,
  не блокируют первую волну модулей.
