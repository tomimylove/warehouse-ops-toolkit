# Weekly meeting

Статус: спека согласована в обсуждении, реализация поэтапная (см. «Этапы»).
Раздел навигации: Operations → Weekly meeting (`/operations/weekly-meeting`).

## Зачем

Сейчас еженедельная планёрка склада живёт в большом Excel-файле «Action
log»: ответственные каждый день обновляют там свои пункты, раз в неделю
руководитель разбирает их с сотрудниками, через пару дней отчитывается
перед менеджментом, а файл копируется под новую неделю.

Мы **не воспроизводим Excel**. Из него берётся только суть процесса
(обновление → планёрка → отчёт), а инструмент строится по общепринятым
практикам таск-менеджеров (Jira, Asana, Monday, Linear).

## Принципы

1. **Weekly meeting — вид над Tasks, а не отдельное хранилище.** Данные
   вводятся один раз, в Tasks. Здесь они собираются под неделю.
2. **Неделя — окно на таймлайне, а не копия данных.** Незавершённые эпики
   и задачи никуда не переносятся и не копируются, они остаются как есть и
   попадают в текущую неделю по правилу «активно в этом окне» (срок,
   движение, недельное обновление).
3. **История — это запись, а не копия задач.** При закрытии недели
   сохраняется лёгкий снимок (см. ниже), чтобы прошлую неделю можно было
   открыть «как о ней отчитались», а не в сегодняшнем состоянии.
4. **Универсальность важнее подгонки.** Всё, что можно сделать общим
   механизмом Tasks (таблица, эпики, права), делается там, а не внутри
   Weekly meeting.

## Термины

- **Категория** — доска (`Board`). Постоянные: Quality management,
  Warehouse Execution, Stock control; остальные меняются редко. Ответственных
  за категорию пока нет (три супервайзера есть в оргструктуре, но в модели
  данных не отражены; при необходимости ответственный доски добавляется
  позже).
- **Эпик (Epic)** — крупная работа, объединяющая несколько задач. Заменяет
  Goal из Excel. Это строка `Task` особого типа, лежит на доске-категории.
  Задачи эпика лежат **на той же доске**, что и сам эпик (эпик не охватывает
  несколько досок).
- **Владелец эпика (Epic owner)** — один ответственный пользователь.
- **Задача** — карточка внутри эпика или вне него. **Подзадача** — шаг
  внутри задачи, как сейчас.
- **Недельное обновление** — текст «что сделано / результат» по эпику за
  конкретную неделю. Замена заметок в ячейке Excel.
- **Safety talk** — еженедельный живой митинг по технике безопасности (не
  планёрка). У него есть ведущий и тема.

## Иерархия и правила эпика

`Epic → Task → Subtask`.

- У эпика есть владелец. Если он задан, у задач внутри исполнитель
  **необязателен**.
- «Эффективный ответственный» задачи в таблицах и отчётах: исполнители
  задачи, а если их нет, то владелец эпика.
- Владелец эпика может закрывать, редактировать и переназначать задачи
  других людей внутри своего эпика. Удалять сам эпик по умолчанию нельзя.
- Прогресс эпика считается по его задачам.
- Завершённые эпики не уезжают на «другой лист»: достаточно фильтра
  `Completed` (по умолчанию скрыт).

## Модель данных (черновик)

- `Task.type`: `TASK` | `EPIC`.
- `Task.epicId` → `Task` (эпик); у эпика `epicId` пусто.
- `Task.ownerId` → `User` (используется у эпиков).
- `Task.sourceUrl` — необязательная ссылка на источник («с чего началось»,
  бывшая колонка Subject).
- `WeeklyUpdate`: `epicId`, `isoYear`, `isoWeek`, `authorId`, `text`,
  `blocker`, метки времени. Одна запись на эпик и неделю, редактируется.
- `MeetingWeek`: `isoYear`, `isoWeek` (уникальны), `theme`, `summary`
  (резюме для менеджмента), `closedAt`, `closedById`, `snapshot` (JSON).
- `MonthTheme`: `year`, `month`, `theme`.
- `SafetyTalk`: `isoYear`, `isoWeek`, `presenterId` (пользователь,
  необязателен), `topic`, `notes`; документы и фото — вложения (нужно
  файловое хранилище).
- Метка «может вести safety talk» — флаг на пользователе. Когда появится
  Staff (отдельный большой проект: ротации, оргструктура, табель, профили,
  сотрудники без доступа в систему), метка и ссылка ведущего переезжают на
  запись сотрудника.

### Что в снимке закрытой недели

Не копии задач, а запись отчёта: по каждому эпику заголовок, категория,
владелец, статус (колонка доски), срок, прогресс (сделано/всего), недельное
обновление, флаг блокера; плюс счётчики недели (выполнено, в работе,
отложено, просрочено), тема недели и safety talk.

## Виды

1. **Table view** — универсальный вид Tasks, **заменяет List**. Настоящие
   колонки (эпик/задача, ответственный, срок, статус, приоритет, прогресс),
   группировка по доске, сортировка, фильтры, скрываемые колонки. Развивается
   дальше как отдельный инструмент.
2. **Режим планёрки** — Table с контекстом недели: колонка недельного
   обновления, быстрая правка срока/приоритета/исполнителя на месте.
3. **Дашборд для менеджмента** — отдельная вкладка: цифры недели, разбивка
   по категориям, выделенные эпики, резюме руководителя, выгрузка.
4. **Шапка недели** — номер недели и период, тема недели (позже связана с
   HSE-топиками), тема месяца, safety talk (аватар ведущего и тема, клик —
   детали и документы, листание по неделям, календарь), ниже виджеты для
   произвольных данных (годовой план и др.; наполнение — позже).

Формат выгрузки дашборда (PDF / Excel / ссылка) — открытый вопрос.

## Дополнительные возможности

1. **Что изменилось с прошлой недели.** Авто-дифф: завершено, сдвинулось,
   новое, просрочено. Источник — журнал активности задач.
2. **Залежавшиеся эпики.** Метка «N недель без движения».
3. **Кто не написал обновление.** Подсветка эпиков без недельного
   обновления перед планёркой, напоминание владельцам.
4. **Решение → задача в один клик** прямо на планёрке.
5. **Черновик резюме для менеджмента** по изменениям недели; руководитель
   правит его вручную.

## Права

Права гранулярные: по модулям и по функциям, как описано в
`ARCHITECTURE.md` (раздел 11).

Weekly meeting:
- `weekly-meeting:view` — открывать модуль;
- `weekly-meeting:edit-update` — писать недельные обновления;
- `weekly-meeting:close-week` — закрывать неделю, править резюме;
- `weekly-meeting:view-dashboard` — дашборд и выгрузка;
- `weekly-meeting:manage-safety-talks` — расписание и ведущие;
- `weekly-meeting:upload-documents` — документы и фото к safety talk.

Права владельца эпика (действуют **только внутри эпика, владельцем которого
является пользователь**; настраиваются переключателем в настройках роли, а
не отдельной галочкой на каждом эпике):
- `tasks:epic-owner.close-tasks`;
- `tasks:epic-owner.edit-tasks`;
- `tasks:epic-owner.reassign`;
- `tasks:epic-owner.delete-epic`.

В роли по умолчанию первые три включены, удаление эпика выключено.

## Safety talk: расписание

Ведущие берутся из пользователей с меткой, ротация по списку, график
строится на несколько месяцев вперёд автоматически и правится вручную
(поменять местами, пропустить). Ведущий не обязан иметь аккаунт в будущем,
но пока модель опирается на пользователей системы.

## Этапы реализации

1. Эпик (`type`, `epicId`, `ownerId`, `sourceUrl`), права владельца эпика,
   Table view вместо List.
2. Неделя как окно, недельное обновление, режим планёрки, «что изменилось»,
   «залежавшиеся», «кто не написал обновление».
3. Safety talk: метка на пользователе, расписание, шапка недели. Документы —
   после появления файлового хранилища.
4. Закрытие недели и снимок, дашборд менеджмента, выгрузка, черновик
   резюме, «решение → задача».

## Вне рамок первой версии

Протокол планёрки, виджеты шапки, статус «как идут дела» (On track / At
risk / Off track), интеграция со Staff и HSE-топиками, ответственный за
категорию.
